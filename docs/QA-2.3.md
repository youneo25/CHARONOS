# CHARONOS 2.3 검증 기록

검증일: 2026-10-15 (Asia/Seoul). Windows 11 x64, MSVC 2022, Qt 6.10.3, FFmpeg 8.1, Release.

## 재생 병목 측정

공유 캐시가 선읽기 요구량보다 작은 경우 기존 스케줄러가 현재 프레임을 밀어낸 뒤 같은 프레임/GOP를 계속 디코딩하는 문제를 확인했습니다. 변경 전 `FrameServer::pickLocked` 및 중간 프레임 캐시 범위를 초기 소스대로 복원한 별도 비교 실행 파일을 만들고, 동일한 디코더/측정 코드로 변경 후 실행 파일과 순차 측정했습니다. 앱 전체의 구버전/신버전 비교가 아니라 캐시 스케줄링 변경을 분리한 비교입니다.

256MiB 캐시, 150ms 선행 준비, 영상 앞부분 약 3초, 1ms 확인 간격. 각 영상마다 순차 디코딩/색 변환 180프레임도 별도로 측정했습니다. 수치는 단일 실행의 관측값이며 하드웨어와 OS 부하에 따라 달라집니다.

| 영상 | 원본 FPS | 기존 공급 FPS | 수정 공급 FPS | 기존 캐시 누락 | 수정 캐시 누락 | 디코딩한 프레임 기존 → 수정 | 탐색 기존 → 수정 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 1920×1080 H.264 B프레임 | 23.976 | 19.23 | 23.95 | 25 | 0 | 1002 → 81 | 19 → 1 |
| 3840×2160 H.264 Long GOP | 24 | 11.29 | 23.90 | 43 | 0 | 228 → 73 | 7 → 1 |
| 1920×1080 ProRes | 30 | 29.92 | 29.86 | 3 | 0 | 630 → 99 | 17 → 1 |

수정 코드의 순차 디코딩/색 변환 속도는 각각 약 589, 119, 283fps였습니다. 이 샘플에서 병목은 디코더 자체의 순차 처리 속도보다 캐시 경쟁과 불필요한 탐색에서 발생했습니다. ProRes는 양쪽 모두 30fps 수준을 유지했지만 비필수 디코딩량이 줄었습니다. 지연된 프레임이 다음 확인 시점에 제공될 수 있으므로 ‘캐시 누락 횟수’는 최종 드롭 프레임 수와 다릅니다.

측정은 디코딩/캐시 공급 경로만 포함합니다. 실제 OpenGL 표시, 복잡한 주석, 오디오 동기화, 타블렛, 여러 시간 길이의 영상 및 대규모 프로젝트의 성능을 보장하지 않습니다. GPU 디코딩은 기존처럼 미구현입니다.

## 정확성과 기능

`frame_verify`로 1080p H.264 B프레임 및 VFR H.264의 전체 순차 프레임, 40개 무작위 탐색, 뒤로 48프레임을 비교해 모두 PASS했습니다. 개별 프레임의 픽셀 해시를 순차 디코딩 결과와 대조했습니다.

QtTest는 기존 검사에 다음을 추가했습니다.

- 새 프로젝트 종류/크기/프레임/FPS/이름 지정, 이전 소스 교체, 취소 시 보존, 빈 프로젝트.
- 영상 밖으로 이동·회전·늘인 도형, 두꺼운 펜, 이미지, 텍스트의 자동 영역과 픽셀 및 가장자리 여백.
- 바깥 자동 포함 해제, 주석 제외, 배율, 투명 PNG/TIFF, JPEG 품질/불투명 배경, 과도한 이미지 크기 차단.
- 실제 옵션 창과 파일 저장 대화상자를 거쳐 PNG 생성, 입력 중인 텍스트 확정, 활성 B 클립 저장.
- 256MiB/UHD 조건에서 선읽기 수렴과 현재 프레임 보존, 순차 이동, 비활성 시 재디코딩 중단.

최종 기능 검사: **23 passed, 0 failed, 0 skipped**. 원본 로그는 배포 QA 폴더의 `feature-results.txt`입니다. 옵션 창, 새 프로젝트 창, 영상 밖 합성 결과의 PNG도 확인했습니다.

## 설치 패키지

Inno Setup 6.7.3으로 Windows x64 설치 EXE를 빌드했습니다. `tools/verify-installer.ps1`로 배포 폴더의 별도 QA 경로에 실제 설치하고 다음을 확인했습니다.

- 무인 설치 종료 코드 0, 재시작 불필요.
- 설치된 런타임 파일 46개의 SHA-256이 배포 폴더와 모두 일치.
- PATH에서 Qt/FFmpeg/개발 도구 경로를 제외한 상태로 앱을 시작하고 이벤트 루프 준비 및 프로세스 유지 확인. 숨김 창이라 일반 창 닫기 API가 창을 찾지 못해, 준비 확인 후 검사에서 시작한 해당 프로세스만 종료했습니다.
- 무인 제거 종료 코드 0. 앱 실행 파일 및 제거용 등록 항목 제거 확인.
- 설치 폴더 안에 별도로 만든 사용자 파일은 제거 후에도 보존.

설치 검사는 바로 가기와 파일 연결 옵션을 끈 상태로 실행했습니다. 실제 사용자의 파일 연결을 바꾸지 않았습니다. 기존에 실행 중인 2.2 앱도 유지했습니다. 설치 마법사의 언어/바로 가기 선택에 대한 수동 조작 검사는 수행하지 않았습니다. 설치 로그와 원본 결과는 `installer-install.log`, `installer-uninstall.log`, `installer-verification.txt`에 포함됩니다.

설치 EXE는 미서명입니다. Qt/FFmpeg/C++ 런타임을 함께 배포하며, 파일 해시 목록을 제공합니다. 최종 산출물은 F:에 저장하고, 빌드 및 회귀 검사에 필요한 중간 실행 파일/QA 이미지 사본은 기존 C: 프로젝트의 `build-test`에 남겨 두었습니다.
