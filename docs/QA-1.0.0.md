## 1. GPU YUV→RGB 변환과 NVDEC

- 캐시는 이제 `VideoFrame`(평면 Y′CbCr)을 저장하고 뷰어 셰이더가 RGB로 변환합니다. 행렬(BT.601/709/2020/240M)과 범위(limited/full)는 파일의 태그를 따릅니다. 태그가 없으면 720p 이상은 BT.709, 미만은 BT.601.
- 한 프레임의 캐시 크기 (`playback_probe`):

| 소스 | RGBA (이전) | 1.0 | 절감 |
|---|---:|---:|---:|
| 1920×1080 H.264 4:2:0 | 8,294,400 B | 3,110,400 B | **62.5 %** |
| 3840×2160 H.264 4:2:0 | 33,177,600 B | 12,441,600 B | **62.5 %** |
| 1920×1080 ProRes 4:2:2 10-bit | 8,294,400 B | 4,147,200 B | **50.0 %** |

- 디코딩 → 캐시 프레임 처리량 (순차, 1 디코더):

| 소스 | NVDEC | CPU 12 스레드 |
|---|---:|---:|
| HD H.264 B-frame | 642 fps | 557 fps |
| UHD H.264 long-GOP | 156 fps | 114 fps |

  NVDEC 표면은 `av_hwframe_transfer_data`로 캐시 버퍼(NV12)에 한 번에 복사하며 셰이더가 NV12를 직접 읽습니다. 첫 구현(중간 프레임 + 크로마 분리)은 UHD 100 fps로 CPU보다 느렸고, 직접 복사로 바꾼 뒤 위 수치가 나왔습니다.
- NVDEC가 처리하지 못하는 스트림(ProRes, 4:2:2 H.264, 한계를 넘는 해상도)은 첫 프레임 검사에서 감지해 멀티스레드 CPU 디코더로 다시 엽니다. 재생 중 GPU 오류가 나면 같은 프레임을 CPU로 다시 디코딩합니다. 동시에 GPU를 쓰는 파일은 8개로 제한해 VRAM 고갈을 막습니다.
- `Tools › Hardware Decoding (NVDEC)`로 끄고 켭니다. 속성 패널에 클립별 디코더가 표시됩니다.

## 2. 타임라인 (Window › Timeline, 기본 숨김)

- 프로젝트 모델: `TimelineClip { uid, source, in, out }`. 같은 소스를 여러 번 쓸 수 있고(분할), 주석·북마크·메모는 소스 프레임 기준이라 모든 인스턴스에 표시됩니다.
- 회귀 검사 `timelineTrimSplitMoveUndoAndSave`: 분할 → 트림(30–39) → 주석 → 이동 → 4단계 실행 취소 / 다시 실행, `.frvm` 왕복 저장, 트림된 구간 PNG 내보내기에서 타임라인 25 = 소스 35 프레임 확인.
- `.frvm` 버전 6: `timelines[0].clips` 추가. 이전 빌드가 읽을 수 있도록 `sources` 목록을 계속 기록합니다(트림은 무시됨).

## 3. 아이콘 크기 정렬

모든 아이콘의 실제 잉크 영역을 측정해 긴 변을 24 그리드의 17 단위로 맞추고 중앙 정렬, 선 굵기는 1.6 px로 보정합니다. 함께 바뀌는 아이콘(재생/일시정지, 볼륨/음소거 등)은 같은 배율을 씁니다. 검사 `iconsShareOneSize`: 70개 전부 16.0–17.5 단위, 중심 오차 0.75 이내. 결과 시트: `qa-icons.png`.

## 4. MCP 내장

- 앱이 사용자 전용 Named Pipe(`charonos-mcp-<사용자>`, QLocalServer UserAccessOption)에서 MCP(JSON-RPC 2.0, 줄 단위)를 처리하고, `charonos-mcp.exe`가 stdio ↔ 파이프를 중계합니다. 앱이 없으면 실행 후 연결합니다.
- 도구 24개: 상태·소스 조회, 프레임 이미지(PNG), 탐색/재생, In/Out, 주석 추가·조회·지우기, 북마크, 프레임 메모, 점 추적·트랙 목록·모션 분석, 비교·보기·어니언 설정, 타임라인 편집, 프레임 저장, 프로젝트 열기/저장, 콘솔.
- 안전장치: 모든 편집은 일반 명령 경로를 거쳐 실행 취소 가능, 기존 파일 덮어쓰기는 `overwrite=true`일 때만, 저장하지 않은 프로젝트를 버리는 열기는 사용자 확인 대화상자. `Tools › AI Assistant (MCP)`에서 끄기, Claude Code 명령 / JSON 설정 복사.
- 수정한 문제: 브리지가 실행한 CHARONOS가 클라이언트의 stdio 파이프 핸들을 상속해 클라이언트가 EOF를 받지 못하던 문제(핸들 상속 해제 + null 장치), stdin이 먼저 닫히면 응답 전에 종료되던 문제(미응답 요청을 기다린 뒤 종료).

## 9. 안정성 수정

- 속성 패널의 FPS 값을 바꾸면 그 스핀박스 자신의 시그널 안에서 패널을 다시 만들며 위젯을 즉시 삭제해 충돌할 수 있던 문제 → 지연 삭제.
- 오디오 디코딩 스레드: 종료 시 취소, 4시간 초과 사운드트랙 거부, 메모리 부족 예외가 스레드 밖으로 나가 앱이 종료되던 경로 차단, 끝난 스레드 정리.
- 디코더 스레드·트래킹 스레드·내보내기 스레드의 예외(메모리 부족)를 오류 메시지로 처리.
- NVDEC 실패 시 CPU 재시도, 하드웨어 세션 수 제한.
- 프로젝트를 바꾸면 진행 중인 트래킹 취소.
- 캐시 예산을 실제 RAM 범위로 제한(다른 PC에서 가져온 설정 대비).
- 프로젝트 파일 검증: 잘못된 FPS, 중복 소스 ID, 잘못된 클립 In/Out, 비어 있는 타임라인 배열.
- 메모 편집기가 실행 취소/다시 실행 후 이전 내용을 보여 주던 문제.
- 내보내기가 트림된 클립의 소스 프레임을 반영.
- 단축키 기본값 중복을 시작 시 감지.

```bat
build.bat
tools\test-features.bat
build\frame_verify.exe <video> 200            & rem --cpu 로 CPU 디코딩 비교

powershell -File tools\package-installer.ps1 -Compiler <ISCC.exe>   & rem 또는 -NoInstaller
```
